## Platform focus

| Platform | Recommended implementation |
|---|---|
| AI/ML and orchestration services | Python |
| Native Linux robot process | C++ or Python |
| Raspberry Pi / NVIDIA Jetson | C++ for native integration; Python for fast development and AI |
| Node.js backend | TypeScript |
| Browser dashboard | TypeScript over MQTT WebSocket or WebRTC |
| ESP32 / Pico W-class microcontroller | MicroPython over MQTT |
| Agent client | Python FastMCP or TypeScript MCP SDK |

## MicroPython hardware status

| Board or family | Status | Notes |
|---|---|---|
| Seeed XIAO ESP32-S3 | Tested | MicroPython 1.29.0; used by the included sensor, LED RPC, and MCP examples |
| ESP32 family | Compatible target | Requires suitable MicroPython firmware and `mqtt_as` networking support |
| Raspberry Pi Pico W family | Compatible target | Requires RP2 MicroPython firmware with working Wi-Fi support |
| ESP8266 | Constrained target | May require frozen or precompiled dependencies because of memory limits |
| Other MicroPython boards | Evaluate | Requires `asyncio`, sufficient heap, and a network path supported by `mqtt_as` |

## Known cross-language consideration

C++ currently places WebRTC image and audio frames on the data channel. When pairing C++ with Python, disable native media channels in Python (`use_media_channels=False`) and C++ (`useMediaChannels=false`). Python-to-browser deployments can use native media tracks when both peers declare the same media topics.
