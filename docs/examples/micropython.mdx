# MicroPython and embedded devices

MAGPIE lets a microcontroller participate directly in the same system as Python services and C++ robot processes. The default ZMQ transport communicates over TCP without a broker. Install the optional MQTT package when the deployment needs brokered routing, browser access, or easier communication across NAT.

:::info Tested and compatible hardware

The current release has been tested on a Seeed XIAO ESP32-S3 with MicroPython 1.29.0. ESP32, Raspberry Pi Pico W, ESP8266, and other network-capable MicroPython boards are compatible targets subject to their firmware, `asyncio`, memory, and TCP networking support.

:::

## Prepare the board

Install the default package, replacing `COM13` with the board's serial port:

```powershell
python -m pip install mpremote
mpremote connect COM13 mip install github:luxai-qtrobot/magpie-upy
```

Clone the repository to get the examples, then replace `WIFI_SSID` and `WIFI_PASSWORD` in the script you want to run:

```bash
git clone https://github.com/luxai-qtrobot/magpie-upy.git
cd magpie-upy
python -m pip install luxai-magpie
```

The ZMQ examples connect the board to Wi-Fi, bind a direct TCP endpoint, and print the board's IP address. Run the board script and its matching desktop command in separate terminals. Keep these plain ZMQ endpoints on a trusted local network.

## Stream sensor data to a desktop

The sensor example publishes a `DictFrame` containing a counter and the board's free heap every two seconds:

```powershell
mpremote connect COM13 run examples/zmq_sensor_stream.py
```

Read the stream from the desktop, replacing `BOARD_IP` with the address printed by the board:

```bash
magpie-read tcp://BOARD_IP:5555 magpie-upy/esp32-001/sensor --pretty
```

This is direct cross-language interoperability: MicroPython and desktop MAGPIE share the ZMQ multipart format, MessagePack representation, frame envelope, and stream API.

## Send a stream to the board

The reverse example lets the board receive commands or state from a desktop publisher:

```powershell
mpremote connect COM13 run examples/zmq_stream_reader.py
```

Publish values to the endpoint printed by the board:

```bash
magpie-write tcp://BOARD_IP:5557 magpie-upy/esp32-001/command "{'action':'ping'}" --rate 1 --loop
```

The reader uses `delivery="latest"`, so a slow application favors the newest buffered value.

## Control a physical output with RPC

On a XIAO ESP32-S3, start the ZMQ service that controls the active-low user LED:

```powershell
mpremote connect COM13 run examples/zmq_rpc_switch.py
```

Call it from the desktop:

```bash
magpie-request tcp://BOARD_IP:5558 "{'action':'on'}" --pretty
magpie-request tcp://BOARD_IP:5558 "{'action':'off'}" --pretty
```

The device acknowledges each request before returning its result. For another board, change the GPIO and active-high or active-low behavior to match its hardware.

## Expose an MCP tool from the microcontroller

Run the on-device MCP tool server:

```powershell
mpremote connect COM13 run examples/zmq_mcp_tool.py
```

Discover and call its `free_memory` tool through ordinary MAGPIE RPC:

```bash
magpie-request tcp://BOARD_IP:5556 "{'jsonrpc':'2.0','id':1,'method':'tools/list'}" --pretty
magpie-request tcp://BOARD_IP:5556 "{'jsonrpc':'2.0','id':2,'method':'tools/call','params':{'name':'free_memory','arguments':{}}}" --pretty
```

An agent can call the same tool through a desktop FastMCP client and MAGPIE's `McpTransport`. The board itself needs no FastMCP runtime, HTTP server, or operating system—it implements the MCP tool contract through `McpSchema` and ZMQ RPC.

```mermaid
flowchart LR
    D[ESP32 / Pico W] <-->|ZMQ RPC over TCP| M[MAGPIE McpTransport]
    M <--> A[FastMCP client / AI agent]
```

## Optional MQTT examples

Install the MQTT manifest in addition to the default package when the board needs MQTT:

```powershell
mpremote connect COM13 mip install github:luxai-qtrobot/magpie-upy/package-mqtt.json
python -m pip install "luxai-magpie[mqtt]"
```

The repository includes equivalent MQTT examples:

| Example | Board script | Desktop command |
|---|---|---|
| Sensor stream | `mqtt_sensor_stream.py` | `magpie-read-mqtt` |
| User LED RPC | `mqtt_rpc_switch.py` | `magpie-request-mqtt` |
| MCP tool | `mqtt_mcp_tool.py` | `magpie-request-mqtt` or a FastMCP client |

Edit each script's `MQTT_CONFIG` before running it. A public broker is suitable only for demonstrations; use an authenticated broker and topic ACLs for deployed devices.
