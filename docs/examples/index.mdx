## Suggested learning sequence

1. Run one writer and one reader on localhost.
2. Replace streaming with RPC for a command that returns a result.
3. Move both components to MQTT and confirm the application logic remains recognizable.
4. Run different language implementations against the same topic or service.
5. Add a schema and expose one safe method as an MCP tool.
6. Use the CLI tools to inspect the finished deployment independently of your application.

## Patterns worth copying

- **One connection, many components:** share MQTT and WebRTC connections within a process.
- **Stable names:** centralize topic, service, and session identifiers.
- **Explicit shutdown:** close components before shared connections.
- **Timeouts everywhere:** do not allow network calls to wait forever.
- **Transport configuration outside behavior:** load endpoints and credentials from deployment configuration.
- **Test the wire:** include at least one cross-language integration test for every shared contract.
